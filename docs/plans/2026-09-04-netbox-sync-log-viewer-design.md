# Сводка netbox-sync в разделе "Настройки"

Дата: 2026-09-04

## Задача

В dropdown "Настройки" (шапка, шестерёнка) показать статус последнего
прогона `netbox-sync/full_sync.sh`: компактную сводку по 8 шагам сразу в
dropdown, с возможностью развернуть полный сырой лог по запросу.

## Решения (обсуждены и подтверждены с пользователем)

1. **Контент**: компактная сводка (имя шага/статус/время) в самом dropdown
   + кнопка "Развернуть лог" — открывает полный сырой текст в модалке.
2. **История**: только последний прогон. Сами файлы за 30 дней остаются на
   диске (netbox-sync сам их не чистит раньше срока) — список прошлых
   прогонов можно добавить позже, если понадобится.
3. **Live-обновление**: НЕТ автополлинга. Статичный снимок на момент
   открытия dropdown + кнопка "Обновить" (ручной re-fetch).
4. **Размещение в UI**: сводка — прямо в существующем `.nav-settings-dropdown`
   (второй блок под переключателем темы). Полный лог — в модалке,
   переиспользующей существующий htmx-модал-шелл (`#modal-content`,
   `open-modal` событие, `$store.modal`) — тот же паттерн, что у "Справка"/
   "ОС-справочник".

## Найденный попутно баг (исправлен в рамках этой же задачи)

`docker-compose.yml` монтировал `config_backups` для ACL-страницы
относительным путём `../netbox-sync/config_backups`. На проде GitLab-раннер
чекаутит `ip_plan_react` и `netbox-sync` в НЕЗАВИСИМЫЕ build-директории
(`/home/gitlab-runner/builds/<runner-id>/0/a.nikolaev/<project>`) — они не
соседи, относительный путь резолвился в пустую (Docker её тихо создавал)
директорию. Починено через новую docker-compose переменную
`NETBOX_SYNC_DIR` (дефолт `../netbox-sync` для локальной разработки, на
проде — CI/CD-переменная со значением `/opt/scan`, реальный `DEPLOY_PATH`
netbox-sync, см. корневой `CLAUDE.md`). Тот же принцип использован и для
нового mount'а `sync_logs`.

## Архитектура

- **`ip_plan/services/sync_log.py`** — читает и парсит последний
  `full_sync_*.log` из `settings.SYNC_LOGS_DIR` (regex по `full_sync.sh`:
  заголовок с `env`/временем старта, статус-строки `  [Шаг] СТАТУС (Nс)`,
  наличие блока `SUMMARY`). "Выполняется ли прогон сейчас" выводится из
  самого текста — если нет `SUMMARY`, но есть шаг без статус-строки, он
  считается текущим (шаги идут строго по порядку, как в самом
  `full_sync.sh`). Лок-файл `.full_sync.lock` не читаем — не нужен для
  статичного снимка.
- **`config/settings.py`**: `SYNC_LOGS_DIR` — тот же принцип, что и у
  `ACL_CONFIG_BACKUPS_DIR` (путь внутри контейнера, дефолт `BASE_DIR /
  "sync_logs"`, совпадает с точкой монтирования).
- **`docker-compose.yml`**: `${NETBOX_SYNC_DIR:-../netbox-sync}/sync_logs:/app/sync_logs:ro`
  (read-only, рядом с аналогичной строкой для `config_backups`).
- **Views**: `GET /sync-log/summary.json` (JSON для dropdown),
  `GET /sync-log/modal/` (HTML-партиал для модалки, тот же паттерн что
  `help_modal`).
- **Frontend**: `Alpine.data('navSettings', ...)` в `app.js` — заменил
  инлайн `x-data` на кнопке настроек (было только `theme`+`open`, стало
  ещё `syncLog`/`syncLogLoading`/`syncLogError`/`refreshSyncLog()`).
  Fetch — обычный `fetch()`, без CSRF (GET). Разметка — в
  `base.html` (шаблонные `x-if`/`x-for`), стили — в `nav.css`
  (`.sync-log-*`), т.к. dropdown общий для всех страниц, а не только
  таблицы (в отличие от `table.css`, который грузится только на странице
  IP-таблицы через Vite).

## Проверено вживую

Локально (`localhost:8090`, реальные логи `netbox-sync/sync_logs/` за
август): сводка отображается корректно (включая честный "—" для шага,
которого не было в конкретном логе), кнопка "Обновить" работает, модалка
открывает полный лог до самого конца (блок SUMMARY), светлая и тёмная
темы — обе проверены.
